Вход через Google и облачный синк прогресса

Сейчас весь прогресс живёт в localStorage одного браузера на одном телефоне. Ниже — пошаговый план, как добавить вход через Google и хранить те же данные в Firestore, чтобы прогресс не терялся при смене телефона и был виден с любого устройства под одним аккаунтом.

01

Завести проект Firebase

5 мин · без кода
  1. Открой console.firebase.google.com, войди тем же Google-аккаунтом, которым будешь пользоваться в приложении.
  2. «Добавить проект» → назови, например, connor-protocol → «Continue». Мастер настройки периодически меняется: тумблер про Google Analytics может быть на этом же экране, на следующем шаге или не появиться вовсе — в любом из случаев его можно смело отключить (или пропустить), для этой задачи он не нужен и ничего не ломает, если остался включён.
  3. Внутри проекта: значок </> («Добавить приложение» → Web) → назови приложение так же → «Зарегистрировать». Firebase покажет блок firebaseConfig с ключами — он понадобится в этапе 4, скопируй его целиком в заметки.
Важно понимать: ключи из firebaseConfig (apiKey и т.д.) будут видны прямо в коде страницы — это нормально и ожидаемо для Firebase. Они не секретные в том смысле, в каком секретен пароль: защита данных обеспечивается не их скрытостью, а правилами доступа Firestore из этапа 3.
02

Включить вход через Google

2 мин · без кода
  1. В левом меню консоли: Build → Authentication → «Get started».
  2. Вкладка «Sign-in method» → выбрать «Google» из списка провайдеров → включить тумблер → указать email поддержки (свой) → «Сохранить».

Больше здесь ничего настраивать не нужно — Google как способ входа теперь доступен проекту.

03

Завести Firestore и правила доступа

5 мин · немного кода
  1. В меню консоли: Build → Firestore Database → «Create database» → режим «Production mode» → выбрать регион (любой европейский, ближе к тебе) → «Enable».
  2. Вкладка «Rules» — заменить содержимое на правило ниже и нажать «Publish». Оно разрешает читать и писать документ только тому, кто в него залогинен как владелец.

firestore.rules

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid}/state/main {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
Зачем это отдельным этапом: без явного правила Firestore в режиме Production по умолчанию блокирует вообще всё чтение и запись. Это правило — единственное место, где можно ошибиться так, что чужой прогресс станет читаемым, поэтому стоит перепроверить его один раз здесь, а не на глаз в коде приложения.
04

Подключить SDK к приложению

5 мин · код

В index.html, перед закрывающим тегом </head> (после существующей строки со шрифтами) добавить три скрипта и вставить свой firebaseConfig из этапа 1:

index.html · <head>

<script src="https://www.gstatic.com/firebasejs/10.13.0/firebase-app-compat.js"></script>
<script src="https://www.gstatic.com/firebasejs/10.13.0/firebase-auth-compat.js"></script>
<script src="https://www.gstatic.com/firebasejs/10.13.0/firebase-firestore-compat.js"></script>
<script>
  const firebaseConfig = {
    apiKey: "...",
    authDomain: "connor-protocol.firebaseapp.com",
    projectId: "connor-protocol",
    // ...остальные поля — вставить как скопировалось из консоли
  };
  firebase.initializeApp(firebaseConfig);
  const auth = firebase.auth();
  const db = firebase.firestore();
</script>

Используется «compat»-сборка SDK — она работает через обычные <script>-теги и глобальный объект firebase, без сборщиков и модулей. Это совпадает с тем, как уже устроено приложение (один файл, никакого npm), так что менять больше ничего в структуре не придётся.

05

Кнопка входа и статус пользователя

10 мин · код

В шапку (header.top) — рядом с плашкой ранга — добавить кнопку входа/статус:

index.html · разметка шапки

<button class="btn" id="btnGoogleAuth" style="font-size:11px; padding:6px 10px;">Войти через Google</button>

И в конце основного скрипта — обработчик клика и слушатель состояния входа:

index.html · основной <script>

document.getElementById("btnGoogleAuth").addEventListener("click", () => {
  if (auth.currentUser) { auth.signOut(); return; }
  auth.signInWithPopup(new firebase.auth.GoogleAuthProvider());
});

auth.onAuthStateChanged(async (user) => {
  const btn = document.getElementById("btnGoogleAuth");
  if (!user) { btn.textContent = "Войти через Google"; return; }
  btn.textContent = `Выйти (${user.displayName?.split(" ")[0] || "аккаунт"})`;
  await syncFromCloudOnLogin(user.uid);
});

Функция syncFromCloudOnLogin — из следующего этапа: она решает, откуда брать данные при входе — из облака или поднять то, что уже накопилось локально.

06

Переписать load() / save() на Firestore

15 мин · код, самый важный этап

Сейчас в приложении:

index.html · как сейчас

function load() {
  try {
    const raw = localStorage.getItem(STORE_KEY);
    if (!raw) return defaultState();
    const parsed = JSON.parse(raw);
    return Object.assign(defaultState(), parsed);
  } catch (e) { return defaultState(); }
}
function save() {
  try { localStorage.setItem(STORE_KEY, JSON.stringify(state)); } catch (e) {}
}

localStorage остаётся как есть — это офлайн-кэш и подстраховка. Поверх добавляется синк с Firestore, когда есть вход и сеть:

index.html · добавить рядом с load()/save()

function save() {
  try { localStorage.setItem(STORE_KEY, JSON.stringify(state)); } catch (e) {}
  if (auth.currentUser) pushToCloud();
}

let pushTimer = null;
function pushToCloud() {
  // Небольшая задержка (debounce), чтобы не писать в Firestore на каждый
  // клик отдельно — только когда изменения улеглись.
  clearTimeout(pushTimer);
  pushTimer = setTimeout(() => {
    const uid = auth.currentUser.uid;
    db.collection("users").doc(uid).collection("state").doc("main")
      .set({ ...state, updatedAt: Date.now() })
      .catch((e) => console.error("Не удалось сохранить в облако:", e));
  }, 1500);
}

async function syncFromCloudOnLogin(uid) {
  const ref = db.collection("users").doc(uid).collection("state").doc("main");
  const snap = await ref.get();
  if (!snap.exists) {
    // В облаке пусто — это первый вход. Поднимаем то, что уже накоплено
    // локально, чтобы старый прогресс не потерялся при переходе на аккаунт.
    await ref.set({ ...state, updatedAt: Date.now() });
    toast("Локальный прогресс загружен в облако");
    return;
  }
  const cloud = snap.data();
  // Более новая версия побеждает — по времени последнего сохранения.
  const localIsNewer = (state.meta?.updatedAt || 0) > (cloud.updatedAt || 0);
  if (!localIsNewer) {
    state = Object.assign(defaultState(), cloud);
    save();
    renderAll();
    toast("Прогресс загружен из облака");
  }
}
Почему именно так: при одном пользователе на одном активном устройстве конфликтов записи не бывает, поэтому не нужна сложная синхронизация — «более новое побеждает» полностью достаточно. localStorage остаётся источником правды офлайн: если сети нет, приложение работает как сейчас и просто досинхронизируется, когда сеть появится (следующий вызов save()).
Не забыть: в defaultState() нет поля updatedAt — его стоит завести (например, внутри meta) и проставлять при каждом save(), иначе сравнение «что новее» работать не будет.
07

Разрешить домен GitHub Pages

2 мин · без кода
  1. Firebase Console → Authentication → Settings → Authorized domains.
  2. «Add domain» → вписать адрес вида твой-логин.github.io (без https:// и без пути к репозиторию).

Без этого шага вход через Google будет работать только при открытии файла локально или на localhost — на реальном адресе GitHub Pages окно входа выдаст ошибку домена.

08

Проверка перед тем, как показывать кому-то ещё

10 мин
  • Вход через Google на реальном адресе GitHub Pages (не только локально) открывает окно выбора аккаунта и возвращает в приложение.
  • После первого входа с уже накопленным локальным прогрессом — в Firestore (вкладка Data в консоли) появился документ с теми же данными.
  • Отметить что-нибудь в приложении → обновить страницу → прогресс на месте.
  • Выйти → зайти на другом браузере/устройстве тем же аккаунтом → виден тот же прогресс.
  • Выключить вайфай, отметить тренировку — приложение не падает, работает как обычная локальная версия.
  • Открыть Firestore Rules Playground (или попробовать зайти вторым тестовым Google-аккаунтом) и убедиться, что чужой документ не читается.
Резервную копию всё равно стоит оставить: кнопки «Скачать резервную копию» / «Восстановить из файла» никуда не делись и продолжают работать поверх облака — лишняя подстраховка на случай, если что-то в синхронизации пойдёт не так, ничего не стоит.
